# BintangToba Agent Instructions

## Mandatory pre-work

Before changing files, debugging, refactoring, styling, writing content, running release work, or answering with implementation status, load and follow all project skills:

1. `bintangtoba-portfolio`
2. `bintangtoba-design`
3. `bintangtoba-engineering-integrity`

Use the skill tool when available. If the skill tool is unavailable, read these files directly before working:

- `.opencode/skills/bintangtoba-portfolio/SKILL.md`
- `.opencode/skills/bintangtoba-design/SKILL.md`
- `.opencode/skills/bintangtoba-engineering-integrity/SKILL.md`

Do not treat any task as routine enough to skip these instructions.

## Work standards

- Keep all visible portfolio identity centered on Bintang Toba.
- Keep the language toggle and light/dark toggle visible and working.
- Import app-level components through `src/components/index.js`.
- Keep files grouped by responsibility.
- Prefer direct fixes over noisy patches.
- Never hide errors, warnings, failed builds, or incomplete work.
- Never claim work is complete unless relevant verification has actually run.

## Verification

Run the relevant checks for the change. For normal code/style edits, run:

```bash
npm run build
```

Report honestly what was changed, what was tested, and anything that remains unverified.
